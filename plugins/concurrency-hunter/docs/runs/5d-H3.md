# 5d run H3 — анализ в месте решающего вызова

Issue [#279](https://github.com/dlin10/ai-coding-plugins/issues/279), база `4c4686cd`.
Ран реализует последнюю поправку ADR 0029: библиотечное тело получает один
решающий вызов программы вместе с производителями его receiver и аргументов.
Для решающего gap сначала читаются записи моделей; обычный ран читает сгенерированный
слой и ничего не генерирует. Генерация осталась у записи моделей репозитория
и переписи владельца. AI-ступень остаётся за фазой 5e, #272.

## Причина и механизм

Прежний внутренний input допускал все тела одной сборки на всех прямых вызовах
программы. Он позволял измерить библиотеку, но отвечал и на вызовы, которые
проверку находки не решали. `GapDecisions` теперь сохраняет с проверкой её
`CallIdentity`, не меняя `GapCheck`, uncertainty, score, fingerprint и формат
находок. `ProducerCalls` идёт по происхождениям решённой кучи на восемь шагов,
включая allocation и отдельный вызов конструктора. `DecidingCalls` в Core
определяет пакет, dispatch и исполнимое тело, `CallSiteRounds` сначала считает
достижимые библиотечные тела без summaries и кучи, затем наращивает допуск.
`CallSiteAdmission` различает вызовы по телу, span, target и ordinal, поэтому
изменения lowering не сдвигают identity. `PhaseOneAnalyzer` запускает до трёх
кругов после стабилизации прочитанного слоя и тратит solver budget один раз,
на последнем анализе. `CoveragePlace` — общий владелец записи мест для
`DecidingGaps.Build` и call-site coverage: тело допущенной библиотеки, включая
lambda и local function, названо сборкой и declaration id корневого члена;
место программы сохраняет target-relative path и строку. Analysis не получил
пакетных или проектных зависимостей.

Внутренний input оставлен для withholding семейства, контроля без допуска
и assembly-wide проб. Product path его не передаёт. Граница генератора
1500 тел на замыкание не изменена; отдельная граница допуска ниже не ограничена
временем. Бюджет генерации 900 секунд обычного рана удалён.

  [#417](https://github.com/dlin10/ai-coding-plugins/issues/417); нового issue нет.
- **H3-L2.** Диагноз pipeline-кейса для
  [#418](https://github.com/dlin10/ai-coding-plugins/issues/418) уточнён (D-0026):
  `Execute<TResult>` уже допущен и answered. В Polly.Core
  `Guard.NotNull` передаёт callback в
  `System.ArgumentNullException.ThrowIfNull(object, string)`.

  Встроенная запись, по которой этот делегат не запускается, дала бы High;
  сам ран эту запись не добавляет. Находок с доступом в Polly.Core нет.
  Диагноз записан комментарием в #418, issue остаётся открытым под эту запись.
- **H3-L3.** Место gap в coverage теперь машинно-независимо, но location
  самой находки, если её доступ находится в библиотечном коде, по-прежнему
  может быть путём машины (D-0025). Этот контракт location ран не меняет.
  Заведено как [#424](https://github.com/dlin10/ai-coding-plugins/issues/424) (5d).
