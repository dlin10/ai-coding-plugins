# 5d run L1 — офлайн-ступени компиляции библиотеки

База сравнения — `ac8784a5` (`HEAD` при записи). Требования рана — строка «5d run L1» [PLAN](../PLAN.md), вопрос 183 и [ADR 0028](../adr/0028-a-library-compiles-with-its-own-identity-references-and-sources.md): копия строгоименной сборки и драйвер её члена подписаны public signing её собственным ключом; ошибка, чей id не принадлежит компилятору, библиотеку не портит; набор ссылок берёт дубль пакета и фреймворка по правилу конфликтов SDK, поднимает зависимость до «пола» строк AssemblyRef набора и находит недостающую ссылку самой библиотеки в папке пакетов. Ничего не скачивается. Нового ADR нет, ADR 0028 не правился: его «158» — замер скретч-сборки, ран измерил 162 члена. Исходники по PDB, сеть, режим offline и CS7036 `System.Security.Cryptography` — run L2.

## Решения

- D-0001 — Код-ревью проверяет правки билдера коротко после каждого хода, полная проверка — в конце рана (`gate=targeted; fullGate=final`).
- D-0002 — CoreLib не перегенерируется: `skills/hunt/evals/models/corelib-generation.tsv` не тронут, в записи рана — только вывод `./build/generate-corelib.ps1 -Since` (ADR 0022).
- D-0003 — Приёмка — тест библиотек (15 библиотек eShop и 3 библиотеки demo компилируются с `Reason` равным `null`) и замер членов из списка в репозитории: `build/check-phase5d-runL1.ps1` запускает `generate` по каждому члену и табулирует следующие исходы для этой записи. Число членов уточнено D-0008: 162, а не 158.
- D-0004 — Все три правила набора ссылок строятся под тесты фикстур — конфликт пакета и фреймворка, пол версии зависимости по строкам AssemblyRef и недостающая ссылка из папки пакетов, — хотя реальные цели могут задействовать не каждое.
- D-0005 — Ошибка принадлежит компилятору ровно тогда, когда её id — `CS` и цифры. Любая другая Error-диагностика (ASP0029, SYSLIB5006, всякий `DiagnosticId` из `[Experimental]` и устаревания) отбрасывается до классификации: она не делает библиотеку непригодной и не делает тело `extern`, потому что оригинальная сборка её подавляла и на привязку она не влияет.
- D-0006 — Ключ — blob открытого ключа AssemblyDefinition самого файла библиотеки, читается там, где модуль декомпилируется; пустой blob — сборка без строгого имени, она компилируется без подписи, как раньше. Копия и драйвер подписаны public signing этим ключом; открытая копия называет драйвер `ConcurrencyHunter.ModelDriver, PublicKey=<hex ключа>` у строгоименной сборки и голым именем у остальных; драйвер узнаёт друга по простому имени — тексту до первой запятой.
- D-0007 — Края набора ссылок. Фреймворк против фреймворка (`Microsoft.NETCore.App` раньше `Microsoft.AspNetCore.App`) и пакет против пакета остаются как были, по правилу конфликтов SDK идёт только пакет против фреймворка. Пол — старшая версия, с которой на сборку ссылается любая сборка набора; папка версии без совместимой lib-папки полу удовлетворяет, как раньше; когда допустимые версии есть, но ни одна не дотягивает до пола, зависимость остаётся самой младшей допустимой версией и называется с полом. Недостающая ссылка самой библиотеки — пакет с id, равным простому имени сборки, самая младшая версия, чья lib-папка платформы держит сборку не ниже ссылки; ничего не скачивается. Часть о названии недостающей ссылки заменена D-0009.
- D-0008 — Замер и правила остановки. Члены замера — все записанные как `library-does-not-compile` в выводе eShop B3 (146 членов в 15 библиотеках) и в файлах ASP.NET Core demo (16: Mvc.Core 3, Mvc 1, Routing 12), всего 162, список лежит в репозитории; пять членов, которые на `HEAD` уже компилировались, остаются контролем. `System.Security.Cryptography` 10.0 (48 членов demo, CS7036) — вне рана, его деталь только теряет SYSLIB5006. Скрипт рана падает, когда хоть один из 162 отвечает `library-does-not-compile`. Если член ASP.NET Core, получивший сгенерированную модель, сдвигает находку demo (`DemoExpectationTests`), сборка останавливается на этом гейте и ожидания не правятся. CoreLib не перегенерируется (D-0002), версия плагина не меняется.
- D-0009 — `MissingDependencies` по-прежнему называет только пакеты-зависимости: две формы SPEC TD-034b и взятые ниже пола, которые тоже пакеты-зависимости. Сборка, на которую ссылается сама библиотека и которой нет ни в наборе, ни в папке пакетов, остаётся без файла молча; найденная добавляет один файл, а не свою lib-папку. Заменяет часть D-0007.
- D-0010 — Правило «ошибка компилятора» держит один предикат везде, где генерация считает ошибки компиляции: классификация библиотеки, проверка ошибок, внесённых открытием поля, и её базис, список ошибок компиляции драйвера. Не-компиляторный id не отказывает библиотеку, не откатывает единицу открытия и не ломает драйвер.
- D-0011 — План чуть больше порога разбиения (24 016 символов против 22 000) ревьюился как есть: пол и недостающая ссылка в отдельный ран не вынесены.
- D-0012 — Неподвижная точка пола — накопительный пол: он только растёт по кругам разрешения, а версия, поднятая им, не опускается, когда источник пола уходит из набора. Точный пересчёт с откатом не строился.

## Что построено

- Идентичность (R1): `LibraryCompilation.Decompile` читает blob открытого ключа AssemblyDefinition один раз и кладёт его в `DecompiledModule.PublicKey`; компиляция копии получает `WithCryptoPublicKey(publicKey).WithPublicSign(true)` для обычной копии и для рецепт-копии, а прямые вызовы `Decompile` → `CompileModule` в тестах и бенчмарке CoreLib проходят тем же путём. `DriverSynthesizer` берёт ключ у `CSharpCompilation.Options.CryptoPublicKey` копии и подписывает им драйвер члена; `LibraryFieldOpening.FriendAttribute` называет драйвер в `InternalsVisibleTo` с ключом (шестнадцатеричная строка в нижнем регистре) у строгоименной сборки и голым именем у остальных; `_friend` драйвера узнаёт друга по тексту до первой запятой, так что у переопределения `protected internal` члена остаются оба модификатора в обеих формах.
- Ошибки не компилятора (R2): `LibraryCompilation.IsCompilerError(Diagnostic)` — severity Error и id вида `CS` + цифры — единственный владелец правила. Через него идут `LibraryCompilation.Errors` (классификация библиотеки, тела `extern`, деталь отказа — только ошибки компилятора), `LibraryFieldOpening.Open` (проверка ошибок, внесённых открытием, и её базис) и список ошибок компиляции в `DriverSynthesizer.Synthesize`.
- Дубль пакета и фреймворка (R3): `ImplementationAssemblies.Opened` собирает копии каждого простого имени отдельно по lib-папкам пакетов и по каталогам shared-фреймворков, первая по порядку побеждает внутри своей стороны (`Microsoft.NETCore.App` раньше `Microsoft.AspNetCore.App`). Имя, которое дают обе стороны, берётся один раз: старшая версия сборки, затем — только при равенстве — старшая версия файла, при равенстве и её — копия фреймворка. Файл версии читается только при равенстве версий сборок.
- Пол версии зависимости (R4): `Raised` поднимает пол каждого имени до старшей версии, с которой на него ссылается открытая сборка или любая взятая в набор копия, — копия, проигравшая дубль, и строка версии `0.0.0.0` пола не дают, и пол никогда не опускается. `Closure` через `Lowest` берёт зависимость самой младшей допустимой версией, чьи сборки, названные в полах, не младше пола (`Older`); папка версии без совместимой lib-папки полу удовлетворяет и называется «no compatible lib folder»; когда ни одна допустимая версия не дотягивает, остаётся самая младшая допустимая, а `MissingDependencies` называет её как `<id>@<version>: <assembly> older than <floor>`. Новый круг разрешения идёт, только когда пол вырос по сборке, которую держит взятая зависимость, и она младше пола (`HoldsBelow`); разрешение, которому поднимать нечего, — одно замыкание и один просмотр, с чтением nuspec и проверкой отмены, как раньше; кругов не больше предела кругов замыкания, и на пределе остаётся набор последнего круга.
- Недостающая ссылка библиотеки (R5): `ImplementationAssemblies.Unprovided` ищет сборку, на которую ссылается открытая, а набор её не даёт, в папке пакетов — пакет с id, равным простому имени, самая младшая кешированная версия, чья lib-папка платформы держит сборку не ниже ссылки; в набор входит один этот файл. Не нашлась — набор без неё, `MissingDependencies` её не называет.
- Фикстуры (задача 1): `EmittedAssemblies.Image` принимает версию сборки, версию файла, открытый ключ, ссылки на другие собранные сборки и подавленные id диагностик; фикстурный ключ — открытый ключ `System.Runtime.dll` бегущего runtime, прочитанный из метаданных (public signing закрытого ключа не требует); `RequiresEShopTheoryAttribute` — теория, которая, как и `RequiresEShopFact`, пропускается без `CH_ESHOP_ROOT`.
- `ModelGenerator`: описание `GenerationRecord.MissingDependencies` называет пропущенные зависимости и взятые ниже пола.
- Скрипт замера (R6): `build/check-phase5d-runL1.ps1` с версионируемым списком `build/check-phase5d-runL1-members.tsv` (162 строки) запускает `generate` по каждому члену, шесть процессов одновременно, и падает, когда хоть один ответ не получен или равен `library-does-not-compile`; пишет `outcomes.tsv` и `summary.md`.
- Оставлено: следующие исходы 162 членов (`driver-not-synthesized`, отказы словаря, наблюдения, `timeout`) не чинятся, только записаны; `System.Security.Cryptography` 10.0 demo остаётся `library-does-not-compile` из-за CS7036 до run L2; CoreLib не перегенерирован.

## Документы

- SPEC TD-034b, абзац implementation-сборки — предложение о разрешении зависимости: версия — самая младшая допустимая диапазонами, чьи сборки, названные в полах, не младше пола; определение пола (старшая версия, с которой на сборку ссылается сборка, взятая в набор на любом круге разрешения; проигравшая дубль копия и ссылка `0.0.0.0` пола не дают; пол только растёт, и поднятая им версия не опускается), новый круг и предел кругов, зависимость без допустимой версии или с допустимой версией без совместимой lib-папки пропускается и называется (`<id>@<ranges>`, `<id>@<version>: no compatible lib folder`), а допустимая, но ниже пола, остаётся и называется с полом (`<id>@<version>: <assembly> older than <floor>`); предложение о недостающей ссылке — пакет с id, равным имени сборки, самая младшая версия не ниже ссылки, один файл, не нашлась — набор без неё, и запись генерации её не называет. TD-034b, ответ G-6 — `generation.missingDependencies` называет пакеты-зависимости, у которых на диске нет допустимой версии или у допустимой версии нет совместимой lib-папки (обе пропущены), и взятые ниже пола (остаются в наборе); в описании объекта `generation` поле названо «пропущенные зависимости и взятые ниже пола». TD-034c — цель и ключ файла члена implementation-ссылки в компиляциях генерации берутся для версии, которую берёт набор ссылок: самой младшей подходящей на диске не ниже пола, а когда ни одна не дотягивает до пола, — самой младшей подходящей. Последний случай держит ячейка `ReferenceSetMatrixTests` «lib-папка, сборка младше, выше нет»; SPEC ячейку по имени не называет.
- PLAN — строка «5d run L1» построена, абзац фазы 5d называет run L1 среди построенных и говорит «L1 закрыл вопрос 183», временная граница «Копия библиотеки компилируется без ключа сборки …» снята; порядок ранов не менялся.
- QUESTIONS — вопрос 183 закрыт (→ SPEC TD-034b; ADR 0028).
- ADR 0028, CONTEXT, `demo/expected-findings.json`, `demo/SCENARIOS.md`, `skills/hunt/`, снимок eShop, `GeneratorBoundaryTests`, прошлые `build/check-phase5d-run*.ps1`, версии манифестов и `corelib-generation.tsv` ран не трогал.
