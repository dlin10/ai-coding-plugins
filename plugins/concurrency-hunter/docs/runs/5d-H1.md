# 5d run H1 — отношение запусков, тип получателя и решающие gaps

База сравнения — `f717cd379b6c82e1aa64d0e855bee4392b7062b4` (`HEAD` при записи). Требования рана — первая часть [ADR 0029](../adr/0029-a-deciding-gap-is-answered-by-a-record-the-call-site-or-ai.md): словарь записей `runs` и `receiver`, чтение `sequential-awaited` движком в границах R3 и список решающих gaps в coverage, `metrics` 1.4 и Markdown-отчёте.

## Решения

- D-0001 — После каждого хода фиксов короткая проверка; полная проверка в конце: `gate=targeted`, `fullGate=final`.
- D-0002 — Первоначальная граница включала словарь, решающие gaps и встроенные записи Polly; перенос Polly уточнён D-0003, отсутствие ступени ответа — D-0007.
- D-0003 — Встроенные записи ретраев Polly и приёмка eShop 36 → 2 перенесены в H2 вместе с join своего прохода; порядок H1, H2, L1, L2, H3, C.
- D-0004 — `runs` разрешено только у `invoke-now`, отсутствие равно `concurrent`, писатель его не выводит; `sequential-awaited` требует Task/ValueTask у `Invoke`, разное отношение даёт разногласие записей.
- D-0005 — `receiver` выбирается по статическому типу выражения, generic-ключ — определение; старшинство слоёв сохраняется, внутри слоя более производный ключ точнее, сгенерированный файл ключа не несёт; уточнения — D-0017 и D-0019.
- D-0006 — Продолжения запусков `sequential-awaited` не пересекаются, ожидание задачи вызова даёт join всех запусков; порядок продолжения перед синхронной частью следующего отложен до H2, порог уточнён D-0016.
- D-0007 — Перечисляются только оставшиеся решающие gaps, без поля ступени: известная запись отвечает до анализа и gap не создаёт; анализа без записей ради списка нет.
- D-0008 — Список виден в `metrics` 1.4 (`coverage[].decidingGaps`) и Markdown coverage каждого scope: callee, fingerprints с проверками, относительные места вызова; `findings.json` не меняется.
- D-0009 — Два кейса `project-model-*` с ожиданиями до кода: ожидаемые запуски и ключ получателя; сдвиги demo объясняются.
- D-0010 — Неприменимый ключ получателя отвергается на шаге проверки члена; правило усилено D-0017 требованием сборки и формы `T:` id.
- D-0011 — Join всех запусков стоит на ожидании задачи вызова, а у члена без задачи — на возврате; первоначальный порог ждущего исполнения заменён D-0016.
- D-0012 — Места решающего gap берутся из `SemanticGap.Sites`, gaps идут по materiality и callee, находки — по fingerprint.
- D-0013 — Вопрос 188 закрывается ссылкой на ADR 0029, сидингу и Polly остаются вопрос 189 и H2; прежние находки demo, 36 находок eShop, ответы evals, CoreLib и Passed-кейсы защищены, модели demo перезаписываются; сохранность групп уточнена D-0023.
- D-0014 — Движок создаёт задачу вызова `sequential-awaited` и без `result`; кейс ожидания — однократно зарегистрированный hosted service, кейс получателя — `reads-deep` у `TextWriter.Write(object)` и чтение в другом исполнении.
- D-0015 — PRD FR-21 и SPEC разрешают доказательство порядка только отношением `sequential-awaited` встроенной или проектной записи; модель никогда не доказывает защиту, сгенерированная модель порядка не доказывает.
- D-0016 — Оба эффекта требуют вызов, который делается один раз исполнением, выполняющимся один раз; ожидание задачи вызова вне этого порога остаётся непроверенным join-ом; источники handle уточнены D-0021.
- D-0017 — `receiver` должен назвать `T:` id типа в сборке члена, совместимого с объявляющим типом; static, конструктор и extension запрещены, в сгенерированном файле ключ отвергает вложенную модель.
- D-0018 — Чтение ограничено одним делегатом с async-целями; не-async обёртка отложена до H2, граница WhenAll/WaitAll снята D-0020.
- D-0019 — Победитель внутри слоя точнее всех подходящих ключей, иначе opaque без следующего слоя; generic сравнивается по определениям; `runs` запрещено в сгенерированном файле; решённые проектным или встроенным слоем вызовы не генерируются; результат `sequential-awaited` у члена с задачей — только `task(…)` или отсутствует.
- D-0020 — `WaitAll` и `WhenAll` уже дают join всех запусков, когда среди их задач есть задача вызова: доказательство проводится для каждого handle группы.
- D-0021 — Источники handle проверяются как у async-вызова: локальные, параметры, возвраты и запись поля ждущим исполнением перед ожиданием на каждом пути; передача задачи другому исполнению через поле join не доказывает.
- D-0022 — Делегат должен быть создан в теле вызывающего из лямбды или группы методов, через копии и phi; параметр, поле и результат вызова — временная граница; комбинация и удаление не дают эффектов по смыслу multicast; join всех запусков строится в `Prove` перед `ProveHandle`, а `ContinueWith` остаётся составным.
- D-0023 — Защищены прежние отпечатки и число групп плюс группы R6; состав групп не сравнивается: fingerprint хэширует регион без контекста, а ключ группы — с контекстом.

## Документы

PRD FR-21 разрешает доказательство порядка только отношением `sequential-awaited` встроенной или проектной записи. SPEC TD-034a описывает `runs`, `receiver`, их проверки, выбор записи для вызова и задачу вызова даже без `result`; полный смысл отношения сохраняет завершение задачи запуска до следующего запуска и завершения вызова. TD-034c запрещает `receiver` и любое `runs` в сгенерированном ответе, TD-065 описывает join всех запусков, TD-039/TD-039a и TD-124 — решающие gaps, разделы отчёта и `metrics` — их представление и схему 1.4. ADR 0029 не назван поглощённым в заголовке SPEC: остальные его решения относятся к H3.

PLAN фиксирует построенный H1, перенос встроенных записей Polly и приёмки eShop в H2 2026-10-27, порядок H1, H2, L1, L2, H3, C и временные границы чтения отношений. Вопрос 188 закрыт ссылкой на ADR 0029. CONTEXT и ADR в задаче документов не менялись; исходники, модели и снимки после задачи 6 не переписывались. Версия плагина не повышается: задача 7 обновляет документы текущего рана, релиз не готовит.

## Фиксы ревью F-0025, F-0026, F-0027 и F-0028

Общее правило F-0025–F-0027 (D-0025): значение проходит границу параметра или поля в доказательстве handle, только если каждый пересекающий её аргумент или записываемое значение разрешается только в проверяемый регион, а все его неизвестные источники оправданы. Вызов, для которого heap не назвал регион, не оправдывается единственным известным регионом соседней альтернативы. `null` не называет другой задачи; пустая запись сама по себе не становится доказанной записью задачи, доминирующей ожидание. Правило общее для spawn-handle, handle async-вызова и задачи вызова; ветви только для задачи вызова, которые оно покрывает, убраны.

F-0025: `BoundToRegion` проверяет аргумент каждого связывающего `CallEdge` у вызывающего экземпляра через общий `BindingExcused` → `SourcesExcused`, сохраняя проверку единственного региона привязки. `BindingExcused` проверяет все регионы значения и защищает рекурсивные привязки набором `_provingBindings`. `CallArgument.CompletedCalls` и `MethodSummaryBuilder.Arguments` сохраняют глубину завершений вместе с прежними `UnknownSources`, `SourceCalls` и `Completions`. `ProveHandle` и `ProveCallTask` уже обращались к одному `SourcesExcused`. `CallsReturn` уже отвергал вызов без региона; он не менялся. Цепи `ReturnsExcused` → `ReturnsExcusedAt` → `ExcusedAt` и `TaskExcused` также сохранены: они доходят до общего доказательства источников. `Prove` и `GroupMembers` сохраняют тот же путь для прямых и групповых ожиданий.

F-0026: полное происхождение записываемого значения сохраняется в `SummaryAccess.StoredValue` и `SummaryReferenceAccess.StoredValue`. `MethodSummaryBuilder.Build` наполняет его для прямой записи поля и записи через ссылку, `CellAccesses` — для записи capture-cell; все три используют существующий `Value`. `FieldStoreDominates` проверяет значение каждой записи у пишущего экземпляра через `BindingExcused`. `FieldStores` перечисляет прямые записи и записи через ссылки; `HeapSolution.ReferenceLocations` экспортирует уже решённые heap-ом места ссылки через существующий `Query`, включая ref-параметры и ref-возвраты. F-0027: `FieldStoreDominates` рассматривает записи из всех экземпляров, поэтому последующая или условная запись другой задачи, а также запись из другого исполнения, не остаётся за пределами проверки происхождения. Корректные записи региона должны доминировать ожидание на каждом пути ждущего исполнения. Общее доказательство использует `Flow.Dominates(stores, join)` и для spawn/async-handle, и для задачи вызова; несколько корректных записей в разных ветках могут вместе закрыть все пути.
