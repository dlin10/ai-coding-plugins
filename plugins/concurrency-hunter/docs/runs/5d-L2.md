# 5d run L2 — исходники библиотеки по PDB и Source Link

**Состояние проверки:** модели demo и базис записаны, шесть замеров выполнены. Полный suite при записи базиса и проверка потерь базиса прошли. Исполняемый gate задачи и финальные gates проверяет сервер.

База сравнения — `bc40f5d6` (`HEAD` при записи), ветка `feature/race-hunter`. Требования — [ADR 0028](../adr/0028-a-library-compiles-with-its-own-identity-references-and-sources.md), его поправка от 2026-11-09 и [строка L2 в PLAN](../PLAN.md), [#278](https://github.com/dlin10/ai-coding-plugins/issues/278). Ран строит получение исходников библиотеки до часов генерации, компиляцию из них с откатом к декомпиляции, виды кода и окончательность ответов, кэш исходников и режим offline в точках входа CLI. Core без источника исходников сохраняет декомпиляцию без сети и кэша.

## Решения

- D-0001 — Исправления после code review проверяются коротко после каждого хода, полная проверка — в конце рана (`gate=targeted; fullGate=final`).
- D-0002 — Текст члена из PDB для входа AI-модели перенесён в H3, [#279](https://github.com/dlin10/ai-coding-plugins/issues/279).
- D-0003 — Offline задаётся параметром `run_start`; скилл передаёт `offline: true`, когда пользователь просит проверку без сети.
- D-0004 — Получение PDB и документов не входит ни в один предел генерации: CPU и аварийный предел члена, предел рана, записи и переписи, `seconds` и стадии ответа; граница общего deadline уточнена D-0013.
- D-0005 — Документ, на который не указывает ни один метод PDB, может отсутствовать; недостающие атрибуты уровня сборки добавляются из того же вывода атрибутов dll, что компилирует декомпилированный путь, без дублей.
- D-0006 — Сумма документа проверяется сначала на полученных байтах, затем после LF→CRLF; компилируется и кэшируется совпавшая форма.
- D-0007 — PDB именует портативная запись CodeView с minor version `0x504D`, а не Windows `ni.pdb` ReadyToRun; ключ серверов — `<lowercase pdb>/<GUID N>FFFFFFFF/<lowercase pdb>`, NuGet спрашивается только с `SymbolChecksum` из dll.
- D-0008 — Перепись фреймворков не регенерируется; приёмка Cryptography — онлайн-генерация 110 членов переписи отдельным скриптом, регенерация — отдельная задача владельца.
- D-0009 — Устойчивая неудача получения допускает хранение ответа на лучшем декомпилированном коде; временная неудача и offline-недоступность дают код только текущего рана; у документов «нет исходников» предшествует «устойчивой неудаче» и обе предшествуют временной.
- D-0010 — Источник исходников строят только точки входа CLI (`run_start`, `metrics`, `generate`); Core по умолчанию, suite и CoreLib tool остаются без сети и настоящего кэша пользователя, CoreLib не регенерируется.
- D-0011 — Флаг CLI — `--offline`, параметр MCP — необязательный `offline: false`; запросы только HTTPS и редиректы на HTTPS, без credentials и cookies; 401/403/407 и отсутствие ответа, включая тело, 30 с пропускают хост до конца рана с исходной устойчивой или временной причиной.
- D-0012 — Сетевой контракт suite проверяется loopback HTTP-сервером, временным кэшем и PDB/документами фикстур Roslyn; реальная сеть — только в скрипте приёмки; nullable при компиляции исходников остаётся Disable.
- D-0013 — Общий 30-минутный deadline MCP-рана остаётся по часам и считает получение исходников; прерванный им ответ — отмена и не пишется.
- D-0014 — Решение переносить прочитанные виды зависимостей в синтетический ответ отменено D-0016.
- D-0015 — Отказ `generate-frameworks.ps1` при коде только текущего рана перенесён в отдельную задачу регенерации переписи; L2 оставляет ей счётчики `sources`.
- D-0016 — Синтетический timeout не несёт видов зависимостей и на лучшем собственном коде хранится по правилу ADR 0032, что бы генерация ни прочитала до обрыва; собственный подготовленный код только текущего рана запрещает хранение и такого ответа; заменяет D-0014.

## Что построено

- `LibrarySources` ищет портативный PDB в dll, рядом с ней, в кэше, затем на Microsoft и NuGet; проверяет id и сумму PDB. Документы получает встроенными, из кэша или по Source Link, проверяет сумму и допустимую замену концов строк. Получение соблюдает HTTPS, запрет credentials/cookies, тайм-аут и пропуск хоста с сохранением причины. PDB и документы записываются атомарно по id PDB в `%LOCALAPPDATA%/concurrency-hunter/sources/`; ран кэш не чистит.
- Один владелец выбирает вид кода и причину по исходам поиска и документов. `LibraryCompilation` разбирает исходники с параметрами PDB, добавляет недостающие атрибуты dll, сохраняет ссылки, public signing и перезапись тел L1; отказ исходной компиляции возвращает декомпилированный путь. Ключ общей компиляции различает исходники и декомпиляцию; право хранить ответ остаётся у вызывающего.
- Подготовка исходников заканчивается до часов члена и учёта времени генерации. Итоговый вид кода после компиляции определяет окончательность ответа. Состояние компиляции принадлежит вызывающему, включая попадание в общий кэш. Синтетический ответ до известного исхода консервативен при временно или offline отсутствующем документе без методов; после успешной компиляции исходников его timeout хранится. Такой ответ применяется зависимым генерациям и scope, но в файл не попадает; синтетический timeout сохраняет правило D-0016.
- CLI строит источник исходников онлайн по умолчанию. `metrics --offline` допустим со всеми режимами генерации, записью и переписью, `generate --offline` и `run_start(offline: true)` читают только диск и кэш. `generate` схемы 5 сообщает `generation.code`, `metrics` схемы 1.6 — режим, число библиотек каждого вида и итоги загрузок. Скилл hunt передаёт просьбу о проверке без сети.
- Добавлены фикстуры и матрицы получения, компиляции, подготовки, кругов и хранения, проверки границы сетевого компонента и offline CLI/MCP. Suite использует loopback и временный кэш. Скрипты `check-phase5d-runL2-gate.ps1` и `check-phase5d-runL2.ps1`, список 110 членов — отдельные средства проверки рана.
- SPEC, PRD, CONTEXT, ADR 0028, AGENTS.md и hunt описывают контракт; строка L2 в PLAN и временное ограничение о недоступности исходников обновлены. Встроенные модели, обе переписи, снимок eShop, ожидаемые находки и сценарии demo, прежние скрипты и манифесты не перезаписываются.

F-0027 (D-0020): ответ 429 или 503 замедляет получение исходников до исчерпания четырёх попыток. Общий `FetchAsync` повторяет запросы Microsoft, NuGet и Source Link; классификатор отмечает повтор и для обычного ответа, и для `HttpRequestException` со статусом, включая proxy tunnel. Между попытками используется `Retry-After` (секунды или HTTP-date, не более 60 с), иначе 1, 2 и 4 с через `RequestTime`. Ожидание находится вне тайм-аута отдельной попытки, до часов генерации, и сразу прекращается отменой. Исчерпанный запрос остаётся случайной неудачей с последним статусом в detail; 429/503 не пропускают хост в следующих обращениях. Правила пропуска после 401/403/407 и тайм-аута, приоритеты R6, детали F-0020 и окончательность ответов не менялись. SPEC и поправка ADR 0028 описывают повтор.

Добавлено 47 случаев: 36 клеток «Microsoft / NuGet / документ × 429 / 503 × ответ / exception / tunnel × успех на четвёртой попытке / исчерпание», каждая с первым и следующим обращением в том же ране; 7 случаев задержек без заголовка, с секундами, HTTP-date, превышением предела и прошедшей датой; 3 отмены во время ожидания на каждом пути; ожидание 60 с с новым тайм-аутом запроса 30 с. Все задержки двигает fake clock, сеть — loopback. Семь проверок задержек до исправления дали **7 Failed, 0 Passed** (`scratch/l2/gates/f0027-red.log`).
