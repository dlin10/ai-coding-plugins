# 5d run A10

Run A10 — ссылки на хранилище struct, остаток рана A9 (вопросы 167–174) и детерминированный решатель (ADR 0021). Каждая
конструкция, дающая ссылку на хранилище struct (`ref`-возврат метода, свойства и индексатора и их `ref readonly`, условный
`ref`, `ref`-локал, `ref`/`in`/`out`-параметр, ячейка `Span<S>` и `ReadOnlySpan<S>`, `ref foreach`, захваченная переменная), —
это хранилище для всех слоёв, а каждая конструкция, дающая значение struct (`Nullable<S>.Value`, содержимое `KeyValuePair`,
`with`, `foreach` по значению, бокс шаблоном), — копия (вопрос 167, матрицы движка и генератора). Закрыт остаток A9: ячейка
переменной лямбды, которую захватывает только прямо вызванная локальная функция (168), версия `ref`-локала (169), массив
аргументов неразрешённого вызова в `unresolved-base` (170), порядок вычисления захваченной цели присваивания (171),
`Nullable<S>`, заполненный записью, которую анализ не видит (172), решатель, ограниченный счётчиком ресурсов Z3 (173), и
сравнители `Nullable` в генерации CoreLib (174).

## Пустая модель хеша

`NullableEqualityComparer<T>.GetHashCode(T?)` в генерации CoreLib отвечал `{}` (замер задачи 3,
`scratch/a10-nullable-hash.md`), хотя зовёт `GetHashCode` значения. Сравнители выбора по умолчанию тут ни при чём: вызов
терялся раньше, в двух слоях.

- Достижимость (ADR 0019). Под правилом построенных типов значимый тип считался построенным только там, где достигнутое тело
  его боксирует, а вызов конструктора значимого типа ничего не строит. Пробную struct драйвер создаёт через `new` и достигает
  только ограниченными (constrained) вызовами — `value.GetHashCode()` в `Nullable<T>`, — которые не боксируют, поэтому её
  `GetHashCode` не достигался. Теперь значимый тип сборки открытого мира (драйвера) построен там, где достигнутое тело его
  создаёт.
- Куча. Движок держит `Nullable<S>` как `S`, которое тот держит, а собственные тела `Nullable<T>` CoreLib в генерации читали
  `hasValue` и `value` как поля; `obj.GetHashCode()` на `T?`, державшем копию `Probe_T`, `WholeProgram.Call` отбрасывал как
  вызов на несовместимом получателе (точный регион `Probe_T` — не `Nullable<Probe_T>`) и не делал экземпляра
  `Nullable<T>.GetHashCode`. Теперь `Nullable<S>` — значение, которое он держит, и в телах `Nullable<T>` CoreLib.

После этого три сравнителя `Nullable` отвечают как их двойники `Generic…` аргумент в аргумент
(`CoreLibGenerationEvalTests.Every_Nullable_comparer_calling_the_default_comparer_answers_as_its_Generic_twin`).
