# 5g run E6 — хвост: формы race, о которых SPEC молчит или правило есть, а свидетельств нет

## Причина

Ран [#437](https://github.com/dlin10/ai-coding-plugins/issues/437) фазы 5g
([#274](https://github.com/dlin10/ai-coding-plugins/issues/274)) берёт хвост: коллекции, шаблоны, вариации и открытые решения.
Целиком ран ещё не открыт; запись начата задачей [#506](https://github.com/dlin10/ai-coding-plugins/issues/506): узнать ответ
анализатора на формы race, которые никто не пробовал, — probe fixtures на минимальном входе, движок не меняется.

Источник списка — сверка каталога поверхности C#/.NET 10 (70 базовых форм, 72 twists) с решающими правилами SPEC, тестами и
Demo: 4 формы, о которых SPEC молчит (F6, F45, F52, F53), 10 форм с правилом без свидетельств (F8, F12, F15, F23, F25, F40, F41,
F42, F49, F62), 9 twists, которые нигде не упражняются (T36, T37, T41, T42, T48, T50, T51, T69, T72), и формы host и ASP.NET Core
из списка работ. Каждую строку сначала сверял с тестами и Demo: ни одна не была закреплена, кроме `System.Threading.Lock`,
взятого через приведение к `object` (`SynchronizationPrimitiveTests`), — его пробовал только в формах без приведения.

## Метод

Каждая проба — минимальный вход и, где он есть, control (та же форма, сделанная безопасной). До запуска записывалась истина run
time: могут ли два access перекрыться и какая документированная гарантия это говорит (Learn; где Learn прямо не говорит —
помечено «выведено»). Ответ анализатора судится по истине, не наоборот. Каждая истина — поведение во время выполнения той
программы, которую fixture изображает, в предположении, что её регистрации и отображения действуют так, как написаны: fixtures
пользуются формой `Startup` всего набора тестов, которую host по умолчанию не привязал бы.

**Harness.** Все пробы идут через `PhaseOneAnalyzer.AnalyzeAsync` — весь конвейер: folded pairing, solver, findings
(`HostedServiceProbe`). Обычная проба — один singleton и два hosted service, каждый выполняет одну инструкцию; пробы startup,
middleware и minimal API — целый исходник со своим `Startup` (`ConfigureServices` регистрирует, `Configure` строит конвейер). Ответ —
множество строк `правило protection ресурс: сторона | сторона`. Ресурс — поля-держатели (`(no field)`, если держателя нет), затем
селектор ячейки (`.[?]`) или `structure`. Сторона — operation, член без параметров (лямбда стоит в члене, который её объявил) и,
если место в исходнике помечено комментарием `/*@name*/`, `@name` той пометки, что лежит внутри span-а access: так пара
различается и там, где обе стороны стоят в одном члене. Ответ и истина сравниваются как множества. Каждая проба объявляет истину
(`Truth`); если ответ другой, проба стоит в `Differences` с текущим ответом и причиной — номером issue или пределом; общая проверка
не даёт записать «разницу», совпадающую с истиной как множество. Где утверждение — о том, какой access собран или какого root нет,
тест читает `AnalysisResult.Accesses` или `AnalysisResult.Roots` того же входа: у пропущенных пар minimal API и массивов и
списков — какая сторона собрана и какой нет, по помеченному месту; у контролей порядка host (startup, два старта) — что обе записи
собраны, прежде чем пустой ответ читается как порядок. Класс жизненного цикла host и проба `IOptions<T>.Value` отмечают
uncertainty (`(uncertain)`); у последней отдельный тест требует, чтобы uncertainty называла неразрешённый вызов
`IOptions<Settings>.get_Value`.

**Заглушки.** `UseMiddleware` и `IMiddleware` добавлены в заглушку `Microsoft.AspNetCore.Http.Abstractions`, `ActionFilterAttribute` —
в `Microsoft.AspNetCore.Mvc.Core`; контракты фильтров (`IFilterMetadata`, `IActionFilter`, контексты) — в новой заглушке
`Microsoft.AspNetCore.Mvc.Abstractions`, на которую ссылается Core; `Microsoft.Extensions.Options` (`IOptions<T>`,
`IOptionsMonitor<T>`, `Options.Create`) — новая заглушка. Обе новые — вне `StubAssemblies.Names`: на них ссылается только проба,
которая их просит. Так пробы видят идентичность фреймворка и встроенные модели переписи (`Options.Create`).

Классы: `LazyInitializationProbeTests`, `LockIdentityProbeTests`, `HostLifecycleProbeTests`, `AspNetCoreProbeTests`,
`TaskCompositionProbeTests`, `LibraryCallbackProbeTests`, `ImplicitSharingProbeTests`, `TwistProbeTests` — 122 случая.

## Что верно

Закреплены как верные: double-checked locking (`DCA1003 partial` на чтении быстрого пути и чтении в `return`, каждое против
записи под lock) и его форма с публикацией до инициализации; lock на переприсваиваемом поле (`DCA1002 different-identity` на
данных, `DCA1003 partial` на самом поле); `System.Threading.Lock` через `object`-локальную, параметр типа и `object`-поле
(`incompatible-mode`), и защита, когда обе стороны берут монитор; `LazyInitializer.EnsureInitialized` без lock;
`BackgroundService.ExecuteAsync` как целиком фоновый (.NET 10) против позже стартующего сервиса и упорядоченный после startup;
minimal API со скаляром в замыкании одного handler; два handler над списком в `static readonly` поле (GET против POST и POST против
POST); primary constructor, чей параметр пишут; `_list = _list.Add(x)`, `ImmutableInterlocked.Update` и его transformer; handler
`Progress<T>` против того, кто сообщает; ребёнок `AttachedToParent` под `Task.Run`; ранний выход из `Task.WhenEach`; классическое
расширение, статический оператор, default interface method, метод в сгенерированном файле, `using`, закрывающий ресурс при живой
работе, callback под lock вызывающего, `await Task.Yield()`; объект и список, переданные неожидаемому вызову или захваченные лямбдой
`Task.Run`; массив в поле в async-callee до `await`, список в поле — и после. Маршрутизированное действие с фильтром — root.

## Пределы — на решение владельца

Не моделируется, ответ закреплён как есть: `Lazy<T>` в любом режиме (фабрика — unknown execution по ADR 0011: FP на поле, которое
пишет конструктор, FN под `PublicationOnly`/`None`; генератор CoreLib отвечает так же) и `LazyInitializer` с lock; middleware (по
соглашению, `IMiddleware` singleton, inline) и фильтры MVC — root-а нет (SPEC 11; тест читает roots), при том что
маршрутизированное действие под фильтром — root и пары даёт; `Progress<T>` и PLINQ — делегат одной передачи не перекрывается сам с
собой; `IOptions<T>.Value` — `get_Value` без модели: race сообщается через unknown effect gap-а с uncertainty, а не записями `Add`;
`ToFrozenDictionary` — чтение источника без модели, пара с `Set` верна, но как unknown effect, а не чтение; присоединённые дети
(`AttachedToParent`) — ребра в SPEC 3.3 нет; finalizer — root-а нет; синхронное завершение `await`.

## Не установлено — убрано из патча (семь проб)

F12, `Select(async …)` (место `_count++` одно, длина источника не моделируется, так что пару двух перечислений не отличить от пары
задач одного перечисления; каждой нужна проверка execution witness или пути вызова каждой стороны):
1. `select-async-counted-then-awaited` — `Count()` до `WhenAll`: нужно утвердить, что стороны пары — задачи двух перечислений.
2. `select-async-awaited-then-iterated` — `WhenAll`, затем `foreach await`: нужно утвердить, что пары между перечислениями нет,
   при паре задач одного перечисления, которую даёт длина.
3. `select-async-enumerated-once` — одно перечисление (`ToList`): нужно отличить пару задач одного перечисления от отсутствия пары.
4. `two-calls-awaited-one-after-the-other` — контроль F12; без трёх проб выше не нужен.

   `IOptionsMonitor<T>.OnChange` — проба не была написана: нужен разрешимый монитор и программный `IOptionsChangeTokenSource<T>`.

F53:
7. `array-pool-buffer-used-after-return` — истина называла бы ячейку, которую ни одна фикстура не показывает; нужна модель

## Что фикстуры не различают

- Кратность: ответ — множество; несколько findings с одним правилом, protection, ресурсом и одной парой мест сливаются.
- Место без пометки — член: две непомеченные стороны в одном члене различает только operation; пометки стоят там, где проба о
  паре таких сторон.
- Два hosted service стартуют по одному разу и не перекрываются сами с собой: формы, где race нужен с тремя исполнителями
  (lost update на списке, который заменяют под lock на нём же), видны только как пары без happens-before.
- `Lazy<T>` `PublicationOnly` против `ExecutionAndPublication` различался бы только моделью с судьбой держателя.
- `DCA1003 different-identity` у lock на переприсваиваемом поле: verdict из-за двух allocation sites или из-за «not one object
  per process» — фикстура не говорит.
- Истины, которые ни один ответ не показал, записаны по правилу `Describe` и не наблюдались: строки с `(no field)`, член фабрики
  в статическом конструкторе (`Holder..cctor`), член finalizer (`Native.Finalize`), члены операторов C# 14
  (`op_AdditionAssignment`, `op_IncrementAssignment`), члены расширений и partial-частей, места check-then-act после исправления
  #510 (`@write`).
- Истина фильтра MVC (экземпляр атрибута общий) выведена.
